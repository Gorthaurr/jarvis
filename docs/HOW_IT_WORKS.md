## 1. КАК ЗАПУСКАТЬ
- **Сервер** (мозг, Fastify+WS, порт **8787**): из `apps/server` → `npx tsx src/index.ts` (НЕ `tsx watch` — падает EADDRINUSE).
  Перезапуск: убить PID на 8787 (`taskkill /F /PID <pid>`) → запустить заново. Логи → `server.out.log`/`server.err.log` (редирект).
  Грузит `.env` из корня репо. Проверка живости: `curl http://127.0.0.1:8787/healthz` → `{"ok":true,...}`.
- **Боевой запуск — супервизор** (задача Windows `JarvisSupervisor` при входе): держит И сервер, И клиент (с 2026-09-24,
  `infra/client-keeper.mjs`: упал → перезапуск с бэкоффом; «Выйти» из трея → не поднимает до следующего входа; клиент
  запущен руками → наблюдает). Перезапуск всего: `Stop-ScheduledTask JarvisSupervisor`, добить node/electron, `Start-ScheduledTask`.
  Вывод клиента → `apps/client/client.out.log`/`client.err.log` (там же фатальные сообщения Chromium).
- **Клиент руками** (Electron, UI/микрофон): `apps/client` → `node scripts/build.mjs` (esbuild) → `pnpm start` (electron). После правок `.ts` клиента — пересборка.
  ⚠️ **Из песочницы агента (Claude Code) Electron падает через ~4 с** — GPU-процесс получает ACCESS_DENIED («GPU process
  isn't usable. Goodbye»), у владельца этого нет. Для тестового запуска из агента — `electron . --disable-gpu-sandbox`;
  проверку «работает ли у владельца» делать через супервизор, не прямым запуском. У агента своё представление файлов
  %APPDATA% (лог клиента, записанный агентским запуском, мог «перекрывать» настоящий) — сверять по `client.out.log`.
- **Расширение** (руки в браузере): загружено в Chrome пользователя. Перечитать с диска после правок `background.js`: `curl -X POST http://127.0.0.1:8787/ext/reload`.
- **БД**: нативный PostgreSQL + pgvector (`DATABASE_URL`); фолбэк PGlite. Docker НЕ используется.
- **Тесты**: `apps/server` `npx vitest run` (~3500); `apps/client` `npx vitest run` (~1000). Typecheck: `npx tsc --noEmit` или `pnpm -r typecheck`. Всё сразу одним раннером — `pnpm verify:quick` / `pnpm verify` / `pnpm verify:full` (профили и состав — `docs/lab/VERIFY.md`).

### 1a. Личный профиль без оплаты API (06.10.2026)

`powershell -NoProfile -ExecutionPolicy Bypass -File infra/run-no-api.ps1 -Brain codex` запускает отдельный сервер
на 8788; `-Brain local` выбирает полностью локальную модель. Скрипт генерирует `.env.no-api`, отдельные данные/PGlite
в `apps/server/data/no-api`, обнуляет ключи облачного LLM/embedding, запускает миграции. Старый `.env` не меняет.
`infra/no-api-profile.mjs` сохраняет существующие STT/TTS, ключи аудиосервисов и все настройки голоса из `.env`.
У Антона это Yandex filipp, скорость 1.2, эмоция good и Deepgram. Смена мозга не должна менять голос.
Только явный `-OfflineAudio` заменяет их Whisper/Windows TTS и очищает облачные аудиоключи.
Таким образом, обычный профиль не требует нового ключа LLM, но сохраняет условия прежних аудиосервисов.
Клиент подключается переменной `PORT`: в другом PowerShell `$env:PORT='8788'; pnpm --filter @jarvis/client start`
(предыдущий экземпляр клиента нужно закрыть). Расширение браузера тоже должно смотреть на выбранный порт.

- `LLM_PROVIDER=codex`: установленный `codex` в PATH (или `CODEX_BIN`), вход **ChatGPT** через `codex login`.
  По умолчанию `CODEX_MODEL=gpt-6-luna`, низкий reasoning effort, одна модель для всех тиров прототипа.
  API-auth отклоняется. Лимит подписки общий с Codex; безлимитность не обещается.
  App Server — экспериментальный протокол; адаптер проверен с `0.155.0-alpha.16.4`. Обновление CLI требует smoke.
  Процесс общий, ephemeral thread на задачу; `dynamicTools` возвращают tool-use в прежний dispatch/confirm Jarvis.
  Встроенные исполнители ОС, браузер, плагины/MCP Codex отключены; `environments=[]`. Ключи не извлекаются из login.
  Переписанная история/новые схемы инструментов пересоздают thread. После ошибки инструмента thread тоже
  пересоздаётся с фактической историей: поздние вызовы старой пачки отменяются до нового планирования.
  Размер контекста берётся из последнего запроса; накопленный расход учитывается отдельно.
  Ошибка/отмена не переключают на платный API.
- `LLM_PROVIDER=local`: Ollama `/api/chat` только на loopback, `qwen3.5:9b-q4_K_M` (6,55 GB, vision/tools).
  Нужен свежий Ollama: 0.18.3 отклонял manifest, проверен 0.40.0. Здесь установлен portable runtime в
  `%LOCALAPPDATA%/Jarvis/runtime/ollama-v0.40.0`; запускатель использует порт 11435, адаптер по умолчанию — 11434.
  Настройки: `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_CONTEXT=131072`. На RTX 5080 16 GB общий расход VRAM был
  около 12 GB. Локальная персона сокращена с 70 151 до 19 894 символов; правила безопасности/честности,
  идентичности и вывода сохранены дословно. Пользовательский контекст и история не обрезаются; при несовпадении
  структуры персоны включается полная версия. Локальный вариант имеет приоритет над lean-персоной.
  При превышении оценки контекста — явная ошибка, а не обрезка истории. Локальный канал — `$0` в учёте API.
- Опциональный офлайн-голос: `STT_PROVIDER=whisper`, `WHISPER_MODEL=Xenova/whisper-base`, CPU/q8; `TTS_PROVIDER=windows` выбирает
  установленный русский SAPI-голос (здесь Microsoft Irina). Ни сетевого синтеза, ни платного fallback.
  Это базовое качество: Whisper-base на контрольной фразе ошибся в окончаниях двух слов.
  Разовое распознавание промаха KWS доступно и для Whisper: отмена/дедлайн 4 с освобождают rescue, поздний текст

### 2a. Текст-драйвер (главный инструмент)
В корне репо есть `_jarvis_cmd.mjs` — WS-клиент, который шлёт `dev.text` в агента (как печать в чат) и печатает ответы.
Протокол: WS на `ws://127.0.0.1:8787/ws` → `client.hello{token,clientVersion,protocolVersion:1}` → ждать `server.hello` →
слать `dev.text{text}`. **ОБЯЗАТЕЛЬНО** отвечать `pong` на `ping` (иначе heartbeat закроет сессию). Авто-подтверждать
`user.confirm.request`. На `action.command` (для клиент-актуаторов) отвечать ЧЕСТНЫМ отказом `action.result{ok:false, error:{code:"runtime"}}` — драйвер не настоящий клиент, выдавать это за успех нельзя (закон 1; `ok:true` учил ложному «готово» и убран из `_jarvis_cmd.mjs` 01.09, из `_qa_battery.mjs`/`_qa_slow.mjs` — 29.09). Telegram/web/MCP идут МИМО — server-side/расширение, поэтому реальны.
```
node _jarvis_cmd.mjs 'отправь голосовое в избранное с текстом тест' 'да, отправляй'
```
Node 22 имеет встроенный `WebSocket` — зависимостей не надо.

  живого клиента; (3) зарегистрировать `app.on("window-all-closed", () => {})` — иначе Electron штатно выходит
  (exit 0, без ошибки) в момент, когда фаза рисования закрывает свои окна, и проба обрывается «ни на чём»;
  (4) IPC из окна (`ipcMain.on("selection:done", …)`) проводить самому — в бою это делает `setupSelection()` в
  `main/index.ts`, в пробе его нет, и промис выделения висел бы вечно; (5) протяжку мышью синтезировать через
  `webContents.executeJavaScript` (dispatchEvent MouseEvent на window) — руки владельца не нужны; (6) читать
  stdout через PowerShell `| Out-File`, а НЕ `| Select-Object -First N` (тот закрывает трубу, и Electron гибнет
  на первой же строке); (7) heredoc в Bash спотыкается о TS-шаблоны с бэктиками — пробу и python-патчи писать
  Write-инструментом в scratchpad. Итог пробы: координаты рамки в экранных DIP на втором мониторе верны, кроп
  области без рамки, `setContentProtection` на прозрачном окне рамку из захвата НЕ убирает (см. CLAUDE.md).
- **Индекс Windows** — прямой ADO-запрос из PowerShell (`Search.CollatorDSO`), см. рецепт в `app-channels.ts`.
- ⚠️ Bash-команда длиннее ~30 КБ падает `ENAMETOOLONG` до исполнения — большие правки писать файлами (Write) и
  python-скриптами в scratchpad, вызывать короткой командой.

## 4. АГЕНТ-ПЕТЛЯ И ЛАТЕНТНОСТЬ
- **Тиры** (`brain/router`): haiku=короткая болтавня/счёт/знание → СИНХРОННО; sonnet/fable=многошаговая/рассуждающая → ФОН
  (мгновенный дворецкий-ack «Сию минуту/Извольте», результат по готовности через `speakResult`). **ВСЕ тиры = модель `claude-opus-4-8`** (в `.env`) — эскалация тира пропускается, т.к. модель одна.
- **Латентность (замерял текст-драйвером):** болтовня/счёт **~2с**, содержательный ответ **~6с**, задача с инструментами
  **~8–15с** (маскируется мгновенным ack). Цель 800мс на тяжёлом ходе не берётся — это норм для Opus.
- **Prompt-кеш §15 РАБОТАЕТ:** префикс [персона][каталог-инструментов][навык] кешируется; повторные ходы — `cacheRead`
  (дешевле/быстрее). Любая мутация `tools[]` рушит кеш → ленивая загрузка холодных инструментов (`tool_load`).
- **max_tokens** — это ВЫВОД за ход (не контекст). Обрыв докручивается (continuation). НЕ слать temperature/top_p/top_k на Opus (HTTP 400). thinking слать МОЖНО — но Opus только `{type:"adaptive"}` (enabled+budget → 400); adaptive = рабочее рассуждение, не убирать.

- **Working memory** (`memory/working.ts` + `working-store.ts`): окно диалога (40 реплик), персист `data/memory/<user>.json`
  — переживает рестарт сервера/клиента и обрыв WS. Resume-окно 120с (`registry.scheduleRemove`).
- **Реестр задач §20** (`brain/tasks/manager.ts` + `task-store.ts`): персист `data/tasks.json` (атомарно, flush на close).
  - `recentTerminal(userId)` — последние СОДЕРЖАТЕЛЬНЫЕ (`stepsDone>0`) терминальные задачи → ответ на «сделал?».
  - `activeForUser(userId, excludeId)` — задачи В РАБОТЕ → ответ «ещё считаю», а не «ничего не делаю».
  - На restore НЕ-терминальная задача → честный `failed` («прервано перезапуском»), не воскрешается.
- **Инжект** обоих блоков → `formatActiveTasks`/`formatRecentTasks` → `UserContextSlot.recentTasks` → `renderDynamic`
  (НЕкешируемый хвост, кеш §15 не страдает).
- **Чекпойнт прерванной задачи (волна C, 2026-07-29):** обрыв по времени/контексту/лимиту шагов/каналу кладёт
  КОМПАКТНЫЙ ЖУРНАЛ прошлого захода (`brain/agent/checkpoint.ts` → `data/checkpoints.json`, одна запись на
  пользователя, TTL 30 мин). **«доделай»** поднимает его и продолжает по ИСХОДНОЙ цели; обещание в терминале
  звучит ТОЛЬКО если чекпойнт реально сохранён. ⚠️ голое «продолжи» — это ещё и tier0-команда плееру, поэтому
  терминал называет ОДНОЗНАЧНОЕ «доделай», а «продолжи» принимается лишь 3 минуты после предложения.
  Журнал гасится УСПЕХОМ продолжения и ОТМЕНОЙ владельца; провал резюме (стаб LLM и т.п.) его не теряет, а
  обновляет (иначе следующее «доделай» повторило бы уже сделанные отправки). В dev-сессии (текст-драйвер)
  чекпойнты выключены: смоук не должен перетирать недоделку владельца.
- **freshContext (важно!):** для «обособленной» новой задачи во время активной агент берёт КОРОТКОЕ окно (`recentTurns(10)`),
  а НЕ ноль — иначе вопрос-продолжение («ты отправил?») терял весь диалог и отвечал «не вижу о чём речь». Память = ВСЕГДА несём окно диалога.
- Episodic (pgvector) — память ОСОЗНАННАЯ: пишем `memory_write` только значимое, НЕ каждую реплику (иначе «странные графики на старте»).

## 7. РУКИ В БРАУЗЕРЕ / РАСШИРЕНИЕ / webK (где я долго буксовал)
- **ExtensionBridge** (`gateway/extension-bridge.ts`): сервер ↔ расширение по WS `/ext`. `request(intent, timeout)` ждёт ответ
  по id. ⚠️ `rejectAllPending` на каждом reconnect/disconnect — поэтому длинная операция, пережившая обрыв WS, ОТКЛОНЯЕТСЯ.
- **MV3 service worker** (`apps/extension/background.js`): засыпает при простое >30с между событиями (alarm clamp ≥30с) →
  WS рвётся → «расширение не ответило». **Фикс: `startKeepAlive()`** — пинг `chrome.runtime.getPlatformInfo` каждые 15с во
  время операции (telegramSend/telegramSendVoice). БЕЗ него длинная файловая операция падала.
- **webK (web.telegram.org/k/) рендерится ТОЛЬКО когда вкладка ВИДИМА** (`visibilityState:visible`). Фоновое/скрытое окно
  → Chrome ставит rAF на паузу → webK висит на `has-auth-pages` с пустым телом (выглядит «не залогинен», хотя сессия есть).
  **Фикс: `openTgTab()`** — переиспользуем УЖЕ открытую вкладку пользователя (DOM построен) ИЛИ активируем её
  (`tabs.update active + windows.update focused`) на время отправки; нет вкладки → создаём ВИДИМОЕ окно (focused:true).
- **Открытие чата:** клик по строке `.chatlist-chat` + НАТИВНЫЙ `.click()` (webK навигирует по href), ждём композер.
  Интерфейс может быть EN → «Saved Messages», не «Избранное» (матчить оба).
- **ТЕКСТ в Telegram — РАБОТАЕТ** (проверено `/ext/telegram`). **АУДИО-ФАЙЛ — СТЕНА:** webK блокирует программную загрузку
  файлов (синтетический `input.change` и drag-drop игнорируются — защита). Настоящее голосовое — только GramJS (нужен api_id,
  которого Telegram-цензура у Антона не даёт: my.telegram.org режет создание app с РФ-IP, страна номера≠IP).
- `browser_open/read/act` — в реальных вкладках через `chrome.scripting` (мышь не трогаем). `browser_inspect` — глаза в DOM.
- **Расширение пропало → доклад владельцу** (`gateway/ext-absence*.ts`, 27.09): учёт в `data/ext-presence.json` —
  `lastSeenAt` по событиям моста, наблюдённое отсутствие (экран не заблокирован) и «Chrome на переднем плане» по тикам
  `client.context`, отказ /ext пиннингом по ID. Chrome ≥ 10 мин (или отказ пиннингом) из ≥ 2 ч без расширения →
  уверенный доклад; ≥ 12 ч без признаков Chrome → мягкий (может раз эскалировать до уверенного). Говорит на реплике
  владельца (чат с шагами + голос коротко, без дат), раз до восстановления связи. Проверить руками: засеять файл (формат — в
  `ext-absence.ts`) в изолированном `JARVIS_DATA_DIR`, сервер на другом `PORT` через `JARVIS_ENV_PATH`, клиент с
  НЕ-dev `clientVersion` (у `_jarvis_cmd.mjs` — dev, он доклад не получает) шлёт `client.context` + `dev.text`.

## 8. ГОЛОС / ДИКТОР-ГЕЙТ / TTS
- **Гейт диктора (`voice/pipeline.ts` + `speaker/`): СЕЙЧАС ВЫКЛЮЧЕН** (`JARVIS_SPEAKER_GATE=0` в `.env`) — биометрия
  ложно отклоняла голос ВЛАДЕЛЬЦА (скоры 0.03–0.7, порог 0.35), Джарвис «не реагировал». Включается, когда `!= "0"` И есть
  enrolled-голос. Owner-only вернуть только после переработки биометрии (банк векторов + AS-Norm), иначе снова отклоняет своего.
- **Wake «Джарвис»** (`voice/wake.ts`): MockWakeWord (текстовый, не акустика). Fuzzy-матч ослышек STT (Гарвис/Джервис/Jarious/jarvis…).

- **Гигиена вывода (`brain/verbalize/`):** `verbalize()` чистит текст ПЕРЕД голосом И чатом — markdown/url/эмодзи + `stripToolCallSyntax`
  (утёкший `<invoke>`/`<parameter>`) + `stripAudioTags` (`[warmly]`). Числа→слова, латиница→фонетика.
- **STT Deepgram** (nova-3): открытие/закрытие WS каждый ход (churn) — открытая боль; persistent WS не сделан (риск).
- **§9 «Уважительная проактивность» (не мешать):** `pipeline.speakQueued(text, urgent?)` + `maybeDrainSpeech` — НЕсрочную
  проактивную речь (итоги фоновых задач) держим, пока `isUserBusy()` (из `client.context`: звонок/полный экран/блокировка),

  читает БД/memSkills. Чтобы научить навыку — `skill_save` (или провайдер `.save()`), не просто положить .md. Recall лексический
