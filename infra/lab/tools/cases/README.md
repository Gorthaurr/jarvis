# Как писать кейсы инструментов

Файл `cases/<область>.cases.ts` с именованным экспортом `cases: ToolCase[]` (загрузчик берёт все `*.cases.ts`).
Формат — `../case-format.ts`; эталон — `sample.cases.ts`. Цель фазы 2: минимум по кейсу на каждую из ~112 схем
(`node --import tsx infra/lab/coverage/cli.ts` покажет, что ещё не покрыто).

## Шаблон

```ts
{
  tool: "fs_delete",                      // как зовёт модель (можно фасад: look / window / audio)
  name: "владелец сказал «да» — файл реально удалён",
  args: { path: "C:/Users/lab/x.txt" },
  seed: { files: { "C:/Users/lab/x.txt": "x" } },   // рабочий стол; по умолчанию — типовой
  before: [{ tool: "fs_write", args: { ... } }],     // предусловия (их эффекты в проверку не входят)
  confirm: "yes",                          // ответ на §14; по умолчанию "no"
  expect: {
    ok: true,
    flags: { declined: false },            // флаги честности: sent / declined / uncertain / observed ...
    asked: 1,                              // сколько раз спросили владельца
    actionKinds: ["fs.delete"],            // ТОЧНАЯ последовательность команд клиенту ([] — не ушло ничего)
    effects: [{ has: "fs.delete" }],       // что ФАКТИЧЕСКИ произошло на «ПК»
    state: (s) => !("C:/Users/lab/x.txt" in s.files) || "файл остался",
  },
  coversTool: "fs_delete",                 // КАНОНИЧЕСКОЕ имя (look{windows} → "window_list")
}
```

## Правила

1. Проверяй ФАКТ, а не «ok:true»: состояние «ПК», эффекты, команды клиенту, вопросы §14, флаги честности.
2. Отказ и недоступность — тоже кейсы: «не выполнено» должно быть видно (`actionKinds: []`, `declined`, `ok:false`).
   Не подтвердил владелец / не смогли спросить / истекло — три разных исхода (закон 1).
3. Тест ценен, только если падает на сломанной реализации: сломай охраняемое (из сохранённой копии, не git) и убедись,
   что кейс краснеет. Ожидания слишком общие (`ok:true` и всё) — кейс декоративный.
4. Нужна сеть/расширение/MCP/рынок — `lab: { ctx: { ext: мок } }`; без мока ожидай `notVerifiable: /причина/`.
   Реально недостижимое без владельца/железа (звук, GUI Windows) — `skip: "причина"` (в покрытие не идёт).
5. `needsKinds` — только если виды команд не выводятся из `expect.actionKinds`/`before`.
6. Кейсы независимы: каждый получает свой «ПК» и свои сторы. Не полагайся на порядок.
